# 歌单直播放与逐首自动加歌

状态：**歌单检测、从歌单点播和逐首加歌已于 2026-11-18 在真机验证**（根因、真机结构和两轮修正见 [KugouCapabilities.md](KugouCapabilities.md)「歌单检测修复」）；超过 100 首的长歌单、PPT 放映和窗口遮挡尚未验收。以下为 2026-11-13 的原始设计记录。2026-11-13 本轮桌面工具无法连接，用户选择先完成代码和自动化测试；没有恢复酷狗、切歌或修改真实歌单。A/B 路线、加歌菜单和加速效果都不能据此标为本机已通过。

## 使用入口与能力门槛

1. 先按下文 §3.1 在酷狗创建「演出歌单」，保持音乐主窗口打开。
2. 面板设置页选择酷狗，填写歌单名，点「保存并检测」；留空关闭。默认关闭，旧配置继续使用搜索。
3. 设置页分别显示「歌单内直接播放」「加入演出歌单」。识别到可靠入口才可用，实际操作成功后才显示「已验证」。歌单或客户端界面改变后点「刷新歌单」。
4. 曲库卡片或酷狗搜索卡片上的 `♫＋` 逐首加歌；搜索结果会先收录到曲库。加歌会试听切歌，操作结束核验暂停，应在演出前使用；已经存在时直接跳过。
5. 歌单成员核验通过后卡片显示「歌单内」。普通点播、上一首、队列下一首及 PPT 联动共用歌单优先入口；日志区显示歌单或搜索路径。

首版不批量加歌、不自动建歌单、不自动下载，不提供手工勾选“已在歌单内”。酷狗模式的自动接歌仍关闭。

## 1. 目标

面板点播一首歌时，如果歌单能力可用并且成员状态不是“不在”，先尝试从歌单播放。不在歌单的歌曲仍走原搜索；入口不可读时保留搜索功能。

## 2. 现在为什么慢

现在的流程在 `Backend/KugouControl/Track.py` 的 `play_track`：

| 步骤 | 耗时 | 说明 |
|---|---|---|
| 清空搜索框、逐字输入、回车 | 约 1 秒 | |
| 等结果页画面换新并停稳 | 1–6 秒 | 结果页是画出来的，读不到文字，只能比对截图等它稳定 |
| 点「单曲」页签再等一次 | 最多 3 秒 | |
| 双击第一行，等窗口标题出现 | 1–12 秒 | 没缓存的歌要联网加载 |

合计一般 5–9 秒，网络慢时到 24 秒超时。另外搜索只能播第一条，第一条不对就播错歌。

歌单路线能省掉前三步的等待。如果歌单里的歌提前下载到本地，第四步的联网加载也省掉。

## 3. 歌单：专门新建「演出歌单」（已定）

不用「我喜欢」或默认列表：里面的歌太多、顺序会变，别的操作也会往里加歌。

面板怎么知道一首歌在不在歌单里，取决于第 4 步的探测结果，见第 5 步的两条路线。

### 3.1 演出前在酷狗里准备歌单（手动操作）

下面的菜单名按酷狗电脑版的通用叫法写，10.2.52.25713 上的实际文字可能略有出入，以界面为准。

**一、新建歌单（只做一次）**

1. 打开酷狗并登录账号。不登录时自建歌单只存在本机，换电脑就没了。
2. 左侧栏找到「自建歌单」（有的版本叫「我的歌单」），点右边的「＋」。
3. 歌单名填 `演出歌单`，回车确认。名字要和面板设置里填的**一字不差**，不要带空格、日期。
4. 歌单名固定下来就不要再改；要按场次区分，就每场清空重加，不要新建第二个歌单。

**二、把歌加进歌单（每场演出前）**

1. 在面板的曲库里列出本场要用的歌（活动组里各分类的歌）。
2. 在酷狗搜索框搜「歌名 歌手」，切到「单曲」页签。
3. **先双击试听，确认版本对**（原唱 / 伴奏 / Live、时长），再往下做。同名歌很多，这一步不能省。
4. 在这一行上点右键 →「添加到」→「演出歌单」。
5. 加完后点开「演出歌单」，核对歌名、歌手和面板曲库里写的一致。面板靠歌名和歌手核验播出来的是不是这首，写法差太多会判成播错。
6. 同一首歌只留一个版本，重复的删掉，免得过滤后第一条不是想要的。

**三、下载到本地（每场演出前）**

1. 打开「演出歌单」，点歌单上方的「下载」（或全选后右键 →「下载」），音质选「标准」或「高品」即可。
2. 等左侧「下载管理」/「本地音乐」里全部显示完成。
3. 标着 VIP、付费的歌需要会员才能下载；下载不了的歌从歌单里拿掉，换一个能下的版本，或者这首歌仍走搜索播放。
4. 会员下载的加密文件只在登录同一账号时能播，演出当天保持登录状态。

**四、演出当天开场前检查**

1. 酷狗主窗口保持打开，不要最小化、不要收进托盘（面板的所有控制都要求这一点）。
2. 断开网络，在「演出歌单」里随便双击两三首，能立刻播出来才算真的下载好了；检查完再连回网络。
3. 关掉酷狗的弹窗、歌词详情页，回到音乐主界面。
4. 在面板设置页点「刷新歌单」，确认「歌单内直接播放」可用；未验证时先试播，成功后才显示「已验证」。
5. 演出期间不要在酷狗里改歌单名、删歌、调顺序。

## 4. 第一步：探测（决定走哪条路线）

已知事实：播放栏上的「播放队列」「我喜欢」按钮 UIA 能读到（`Probes/Results/uia-paused.json`）；搜索结果页读不到文字。**歌单页面里的歌曲行能不能读到，没有验证过。**

要做的事：

1. 在酷狗里手动打开「演出歌单」页面。
2. 用现成的只读探测脚本导出控件树：
   ```bash
   python Probes/KugouUiaTree.py --depth 20 --max-nodes 2000 --values
   ```
3. 在结果里确认三点：
   - 左侧栏的歌单名是不是能按名字定位的控件（Button / ListItem / TreeItem）。
   - 歌单页面里每一行歌是不是独立控件，名字里有没有歌名、歌手。
   - 歌单页面有没有「歌单内搜索」输入框（Edit 控件），能不能用 Value 模式回读。
4. 再打开播放栏的「播放队列」面板，同样导出一次，看队列里的行能不能读到。
5. 把结论写进 `Docs/KugouCapabilities.md`，探测结果存到 `Probes/Results/`。

## 5. 第二步：按探测结果选路线

### 路线 A：歌曲列可读

- 依据可读列标题或带标签的单元格提取歌名、歌手，不从任意行文本猜身份；通过 ScrollPattern 读取虚拟列表。
- 完整读取才允许标记“不在”；滚动失败、未读部分保留未知，坐标对象只在当前工作进程中使用。
- 播放：定位到那一行 → 滚动到可见 → 双击（沿用 `Input.click` 投递消息，不抢焦点）。
- 播放后使用完整歌名、歌手及实际 playing 状态核验；Live、伴奏等版本字样不能省略。耗时待真机测量。

### 路线 B：行读不到，但有「歌单内搜索」框

- 播放：打开歌单 → 写入并回读「歌名 歌手」 → 等待本地过滤 → 点击经真机测量的第一行 → 核验完整身份与暂停到播放的状态变化。
- `PLAYLIST_LAYOUT.first_song` 当前为 `None`；未测量时保持不可用，不能借用搜索结果页坐标。
- 成员记录为未知 / 在 / 不在；明确空结果才记“不在”并回退，错误版本或加载中不回退。耗时待真机测量。

### 路线 C：两样都没有

- 只能按固定位置点（面板保存歌单顺序，按行高算坐标并滚动）。歌单一改顺序就错，**不建议做**，保持现状。

## 6. 第三步：实现（路线 A、B 共用的部分）

按下面顺序做，每一步都能单独测试。

1. **版本档案** `KugouControl/Profiles/__init__.py`
   - 加 `PLAYLIST_LAYOUT`：歌单名、歌单内搜索框和第一行的位置（路线 B）、各步等待上限。和 `SEARCH_LAYOUT` 同样写法，坐标按搜索框高度等比缩放。

2. **歌单操作** 新增 `KugouControl/Playlist.py`
   - `open_playlist(hwnd, name)`：点左侧歌单名，等页面出现。已经在这个页面就跳过。
   - `list_tracks(hwnd)`（仅路线 A）：返回 `[{title, artist}]`。
   - `play_from_playlist(hwnd, pid, title, artist)`：定位或过滤 → 双击 → 等窗口标题 → 用 `same_track` 核验。
   - 失败时抛 `PlaylistMiss`（歌单里没找到，可以回退）或沿用 `TrackFailed` / `TrackLoading`。

3. **入口** `KugouControl/Track.py` 的 `play_track`
   - 开头先判断这首歌要不要走歌单；要就调 `play_from_playlist`。
   - 抛 `PlaylistMiss` 时继续执行现有搜索流程，其余异常照常上抛。
   - 搜索流程本身不改。

4. **进程协议** `KugouControl/Worker.py`、`Adapter.py`
   - `play_track` 的参数里多带一个 `playlist`（歌单名，空表示不用）和 `in_playlist`（是否先试歌单）。
   - 返回数据里带 `via: "playlist" | "search"`，面板和日志能看出走的是哪条路。
   - 走歌单时超时可以缩短（例如 8 秒），回退到搜索时仍用现在的 24 秒。

5. **数据**
   - 设置：歌单名存在哪（建议和控制器设置放一起，`PUT /api/settings/controller` 旁边加一项）。
   - 两条路线共用 `002Playlist.sql` 新增的 `playlist_tracks`，按歌单名和歌曲 ID 保存三态成员结果及名称快照；不修改 `songs` 的现有对外结构。
   - 启动和切换到酷狗后在窗口首次就绪时探测一次；手动刷新使旧记录失效，更换歌单清空，歌曲改名失效，删除歌曲级联清理。

6. **服务层** `Player/Service.py`
   - `_play_song` 把歌单名和标记传给控制器；播完按 `via` 回写标记（路线 B）。
   - 「上一首」「播队列下一首」都经过 `_play_song`，自动受益，不用单独改。

7. **能力自检** `Adapter.capabilities()`
   - 加一项 `play_from_playlist`：「歌单内直接播放」，说明里写歌单名和状态（找不到歌单时写原因）。

8. **前端**
   - 设置页：填歌单名，显示该能力是否可用。
   - 歌曲卡片：显示最近核验的「歌单内」标记，并提供逐首加入入口；按钮提示会试听切歌。
   - 类型同步到 `Template/src/Common/Types.ts` 和 `Docs/ApiContract.md`。

## 7. 第四步：测试

- **单元测试**（不依赖真机，照 `Tests/TestKugou.py` 的写法用假的 runner）：
  - 在歌单里 → 走歌单，不触发搜索。
  - 歌单里没找到 → 回退搜索，结果和现在一致。
  - 歌单路线播错歌（标题核验不过）→ 报错，不记已播。
  - 没配置歌单名 → 行为和现在完全一样。
- **真机验证**（记到 `Docs/KugouCapabilities.md`）：
  - 同一首歌分别走歌单和搜索，各计时 5 次。
  - 歌单里已下载的歌、未下载的歌各试一次。
  - PPT 放映中、酷狗被其他窗口盖住时各试一次。
  - 歌单很长（100 首以上）时最后一首能不能播。

## 8. 风险和限制

- 歌单路线和搜索路线一样依赖酷狗 10.2.52.25713 的界面，改版后要重新量坐标或重新探测。
- 打开歌单页面会离开酷狗当前页面，和现在搜索会跳到结果页是同一类影响。
- 从歌单双击播放后，酷狗自己的「下一首」会顺着歌单往下播。酷狗模式的面板自动接歌保持关闭；请使用「播队列下一首」。
- 成员标记可能过期，明确未命中时才改为“不在”并回退；错误版本、加载或超时不能冒认为不存在。
- 加歌从播放栏的可识别“更多 → 添加到 → 指定歌单”菜单操作，添加后重新从歌单核验。没有可靠菜单或成员核验路径则禁用；仅发送点击不算成功。
- 加歌试听独立于 `_play_song`，不移动队列、不写已播。确认前重查歌曲与唯一选中的歌单，确认后重读完整成员；核验失败返回 `unverified`。若确认可能已经发出，先完整刷新再试。工作进程超时可能中断暂停步骤，需在酷狗中检查并暂停，命令不自动重试。

## 11. 真机探测结果（2026-11-18）

- 侧栏歌单名：List「导航」里的 ListItem，名字是完整歌单名；只在「音乐」页出现，是虚拟列表，只能滚轮。
- 歌曲行：List「单曲」的 ListItem，名字里有歌名、歌手、专辑、时长，可以按 A 路线读取；页面里有隐藏的「共 N 首歌曲」。
- 歌单内搜索框：默认隐藏，点「搜索」按钮才出现。A 路线已可用，B 路线（筛选后按坐标点第一行）不再需要。
- 加歌：播放栏「更多」→「添加到」对话框 → List「选择位置」→「确定」，不是菜单项。

后续复查以替身验证：完全同名也要确认唯一；歌单只有读全才可据缺席写入「不在」；有同歌名、同歌手的多个版本时不会自动选录音。加歌的 43 秒工作预算覆盖读歌单、试听、确认、核验与清理；时间不足会停止提交。这些收紧后的行为和耗时仍待真机验收。
